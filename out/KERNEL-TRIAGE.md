# 内核核心差异三角（27.0.1 → 27.2 GA，无符号）

## 方法
对 `com.apple.kernel` 做函数级差分，用三个信号排序：
1. **dChk**：27.2 版本新增的比较/条件分支数量
2. **size delta**：函数体积增长（修补通常 +数十字节）
3. **指令级差分**：直接看多出来的指令是什么

## 总体
```
A=21792 funcs  B=21842 funcs
配对改动 358 个，另有 94 个无法配对
```

## 已确认的实质改动：0x40969fc（竞态修复）
**27.0.1（旧）**
```asm
add x8, x0, #0x638
swp xzr, x19, [x8]        ; 原子清除 +0x638，取旧值
cbz x19, skip             ; 为空则跳过
```
**27.2（新）**：在对象 `+0x58` 处增加了一套**基于 CAS 的所有权协议**
```asm
mrs  x20, tpidr_el1
ldr  w9,  [x20, #0x4f8]   ; 当前线程 tid
add  x21, x0,  #0x58
casa x8, x9, [x21]        ; 若 [+0x58]==0 则写入 tid
cmp  x8, #0
b.ne <错误路径>            ; 非 0 → 别的线程已持有
...
casl w2, wzr, [x21]       ; 释放：若仍等于自己的 tid 则清 0
cmp  w2, w8
b.ne <错误路径>
```
旧版直接用 `swp` 清字段、没有所有权校验；新版要求"先占位、校验 tid、再释放"。
**这是典型的并发/UAF 类修补**（对应 "improved memory handling" 一类描述）。

## 另一个候选：0x43adc18（空指针加固）
27.2 新增 `cbz x0`（三处）、`tbnz w8,#6` 特性位检查、以及一次释放后清指针
（`str xzr, [x19, #0x18]`）。

## 局限
- 无符号，**无法把候选映射到具体 CVE 编号**（27.2 内核侧共 13 条 Kernel CVE）
- 94 个无法配对函数未纳入分析，可能是被大改的修补点
- 内核核心函数体量大（如 4776 指令），指令级差分噪声高

## 结论
三角法能在**不装 KDK、不做符号化**的前提下，从 358 个改动函数缩到 ~8 个高置信候选，
并已从指令层确认其中至少 1 个是竞态修补。
**但要落到"CVE 编号 + 触发条件"，仍需符号（KDK）或大量人工 RE。**
