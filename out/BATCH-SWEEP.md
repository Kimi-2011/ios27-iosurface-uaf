### 那 4 条「错误返回」逐条看了，是空指针守卫

唯一落 `ASIOKit` 的 4 条（`0x8596cd8` / `0x8596eb8` / `0x85971a4` / `0x8597530`）。
抽 `0x8597530`（28 B → 44 B，`rem == []` 真插入）：

```asm
+ mov  w0, #0x2c2
+ movk w0, #0xe000, lsl #16
+ cbz  x1, +7          ; x1 == 0 → 返回 0xE00002C2
+ cbz  x2, +6          ; x2 == 0 → 返回 0xE00002C2
```

**= `if (!arg1 || !arg2) return kIOReturnBadArgument;`，四指令的空指针守卫。**
另 3 条同形态 + `udf` 断言。

**分级：A（防崩，不是权限判定）。无 S。**

## 结论（到目前为止）

**除 kernel 那条 `0xb348450`，没有任何一条触及权限、凭证或内存破坏。**

27.2 这批改动的形态高度一致：**大量「状态字节置位 / 状态字节读门」+ 少量编译器断言 + 少量空指针守卫**。
这一批的整体性质更像**编译器/框架级的批量改动**（一处结构体新增字段 ⇒ 全类方法都写它），
而不是逐个 kext 的安全修复。

`+0x8` 全局布局位移、Pearl 的 `0x26d–0x2c9` 簇、apfs 的 `0x741/0x742` 簇，都指向同一个解释。
