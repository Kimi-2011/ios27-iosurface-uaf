# 可达面上的审计（iOS 27.0.1，第 10 轮）

> 范围来源：`out/SERVICE-MATRIX.md` 真机实测——本 dev-signed app 能打开 7 个服务。
> 本文件只针对这 7 个服务所对应的 kext，不再从全内核反推。

## 0. 一句话

**188 个可达 handler，按「内部长度字段当下标/偏移」判据审计，命中 0。
但这一轮真正的收获不是这个 0，而是把表扫描器修对了。**

## 1. 修掉的两个扫描器缺陷

### 1.1 stride 不是常数

```
IOSurface    stride 40 + stride 24   两种条款并存
IOGPUFamily  stride 24
```
只按 40 扫，IOGPUFamily 会得到 **0 张表**（本项目前 8 轮一直如此）。
只按 24 扫，IOSurface 会漏掉 120 条那张。

### 1.2 假阳性：`text(va)` 判据太宽

第一版放宽后得到 `AppleM2ScalerCSCDriver: 145 表 / 939 条`。
解码一看全是垃圾：
```
[0] 0xfffffe0007013f90  sIn=65441 stIn=65450 sOut=65458 stOut=65466
```
`0xfffffe0007013xxx` 是内核基址区，计数全在 65300 附近 = **ASCII 字符串被误读**。

原因：内核缓存整体映射，`kext_of(va)` 对任意低地址都返回非空。

**修法（两条硬性条件）**：
1. handler 必须落在**同一个 kext 的 `__TEXT_EXEC`**
2. 计数四字段 ≤ 0x10000 **或** == 0xFFFFFFFF(wildcard)

修后 `AppleM2ScalerCSCDriver` 归零（它确实是手写 switch），其余数字自洽。

## 2. 修正后的可达面

| kext | stride24 | stride40 | 合计 |
|---|---:|---:|---:|
| `IOSurface` | 26 条 | 120 条 | **146** |
| `IOGPUFamily` | 139 条 | — | **139** |
| `IOHIDFamily` | 10 条 | 29 条 | **39** |
| `AppleJPEGDriver` | — | 10 条 | **10** |
| `AppleM2ScalerCSCDriver` | — | — | **0**（手写 switch） |

去重 handler 共 **188 个**。

> 与此前记录的 `242 表 / 1965 入口` 不可直接比较：那批是**全内核 + 单 stride + 宽松判据**，
> 本表是**仅可达 kext + 双 stride + 严格判据**。两者都保留，不要混用。

## 3. 本轮审计判据与结果

**判据**：输入缓冲区（`[args+0x30]` 或 `[args+0x40]`）里的字段被取出后，
未经任何 `cmp/tbz/tst/ccmp` 就用于 `add/lsl/sub` 计算偏移。

**检测器接线验证**（必须先过，否则 0 无意义）：
```
IOGPU 57 个 handler 中
  识别到输入缓冲区指针      11
  从该缓冲区载入过字段      10
  字段载入总次数            71
=> 检测器确实接上了
```

**结果**：
```
188 个 handler -> 命中 0
```

## 4. 这个 0 可信到什么程度

可信的部分：
- 表枚举已修正（双 stride + 同 kext + 严格计数）
- 检测器在 71 次真实字段载入上工作正常
- 有输入缓冲区的 handler 本来就少（派发表里 93.8% 是 `stIn=0`），
  所以这一类的可攻击面本来就窄

**不可信/未覆盖的部分（必须写清）**：
1. 只分析了 handler 前 0x400 字节，更深的代码没看
2. **不跟 `bl`** —— 校验如果在被调函数里，本检测器一律看不见
   （前 9 轮所有假阳性都源于这一条）
3. 手写 switch 的 kext（`AppleM2ScalerCSCDriver`）完全没进这个流程
4. `IOMobileFramebuffer` / `AppleCLCD2` 的 user client 类尚未定位

## 5. 结论

**「内部字段当下标」这一类在可达的派发表面上没有命中。**

但这个结论的强度受第 4 节第 1、2 条限制。
继续在同一判据上深挖的边际收益已经很低 ——
**问题不在判据本身，而在于「静态找未校验」这个方法论在 27.0.1 上已经很难出成果**，
因为 Apple 把长度校验分散在多层（派发表 + handler + callee），
任何单层扫描都会把「别处有校验」误判成「这里没校验」。
