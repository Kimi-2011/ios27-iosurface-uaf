# 新方向：跨代回归检测（iOS 26.x → 27.0.1）

## 为什么换方向
今天全部失败有一个共同根因：

> **"代码变了 ⇒ 大概是安全修复" 是推断，不是事实。**

它在每一处都崩了：
- ASTC/BC/KTX 的大改动 → 实为新增 DDS 格式支持
- CoreText 3 倍膨胀 → 实为加了一层 unordered_map 缓存
- 内核 netif 的"新增 brk" → 实为同一陷阱挪了位置
- JSC/WebKit 的 5274 处"改动" → 编译器/重构噪声

**结论：差分只能给方向，不能给结论。** 而今天的结论全靠差分的语义解读。

## 新方向的核心：把 ground truth 从"推断"换成"存在性事实"

| | 旧方向 | 新方向 |
|---|---|---|
| 问题 | "27.2 改了这里，大概是修了什么洞？" | "26.x 有这个检查，27.0.1 没有——洞在哪？" |
| 依据 | 对改动的**语义解读** | 对二进制的**存在性事实**（有/没有） |
| 需要猜 Apple 意图 | 是 | **否** |
| 可证伪 | 难 | **容易**（反汇编一看就知道有没有） |
| 漏洞状态 | 可能是已修的 | **确定存在于设备正在运行的代码里** |

**关键洞察**：27.0.1 是设备上实际运行的版本。如果某个检查在 26.x 存在、
在 27.0.1 消失，那这个缺失**此刻就真实存在于设备上**，不需要任何推断。

## 为什么选 26.x → 27.0.1（而不是 27.0.1 → 27.2）
- 大版本边界是**重构最剧烈**的地方，检查被重构掉/搬走/漏掉概率最高
- 27.0.1 → 27.2 是维护更新，改动小且多为功能
- 我们手上的 27.0.1 设备就是目标，26.x 只作"参照基线"

## 执行方法（严格验收标准）

一个候选只有在**四条全部满足**时才算数：
1. **存在性**：26.x 的对应函数里有一条明确的比较/边界检查
2. **缺失性**：27.0.1 的同一位置**反汇编可见地没有**这条检查
3. **可达性**：该函数在 app 沙盒内能被触发（有调用链证据，不是"可能"）
4. **实证**：在真机上用构造输入复现异常

**任何一条不满足就不得写入结论。** 禁止用"看起来像""很可能是"这类措辞定性。

## 数据获取
需要 iOS 26.x 的 IPSW（建议 26.5 或 26.6）。下载走 `updates.cdn-apple.com`，
注意：**per-IP 限速约 7–8MB/s，32 线程→3MB/s，64→6，128→7，超过 128 无效**。
只取需要的成员（OS / Cryptex / kernelcache），不要下完整 IPSW。

## 交接铁律
1. **不做盲 fuzz**（已证明 4600 万次零收获）
2. **不做"改动大 ⇒ 修补重"的推断**
3. 每个结论必须附**反汇编片段**或**实测日志**
4. 判断错了要**明确写出来并更正**，不许默默改口
5. 同 bundle id 只能一个 session 用（`com.example.ios27poc`）
