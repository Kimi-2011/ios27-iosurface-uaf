## 唯一确认有实质新增检查的：`nat464_translate_64`

**27.0.1**（`0x3ee82bc`，152 条）关键序列：
```asm
ldrb w27, [x3]        ; 读包首字节
cmp  w27, #0x2c       ; 校验
ldrb w8,  [x0]
ldrh w28, [x0, #2]    ; 读长度字段
ldr  w9,  [x0, #4]
rev  w8, w28
lsr  w8, w8, #0x13
stp  w8, w9, [sp, #0x30]
tst  w28, #0xfffff8ff
```

**27.2**（`0x3f3beec`，166 条）在同一位置**新增**：
```asm
cmp  x27, w22, sxtw   ; ← 64 位值与符号扩展的 32 位长度比较
b.hs <错误路径>        ; ← 越界即跳转
```

### 判读
这是一处**新增的边界检查**：27.0.1 直接对报文长度/偏移做字节序转换和后续处理，
27.2 先做 `(int64)offset >= (int64)len` 检查。属于报文解析的越界防护。

### 可达性（重要）
`nat464_translate_64` 是 **NAT64 的 6→4 转换路径**，只在设备承担 NAT64 网关角色时启用
（个人热点 + IPv6-only 蜂窝、或设备作路由器）。
**普通 app 无法触发**；需要攻击者位于该热点/链路网络上。
→ 属于**远程/邻近攻击面**，不是本地 app 面。

## 结论
网络面**确实存在有实质代码改动的函数**（与用户态那批"全是功能新增/噪声"不同），
其中 `nat464_translate_64` 已确认新增边界检查。但它是 **NAT64 网关路径**，
不是 app 可触达面。
