# 形状匹配方法验证（KDK 方案可行性预演）

## 目的
KDK 到手后，核心动作是"把 macOS 内核的符号按函数形状搬到 iOS 内核上"。
在拿 KDK 之前，先用**已知真值**（27.0.1 ↔ 27.2 的 358 对配对的改动函数）
验证这套方法的精度与覆盖率。

## 方法
- 对每个函数取 **指令助记符序列**（跳过操作数，抗地址/寄存器差异）
- 只接受**两个版本中形状都唯一**的匹配
- 与 `kfunc` 输出的 358 对已知配对比对

## 结果

### 覆盖
```
com.apple.kernel: A=21793 函数, B=21843 函数
形状唯一可配对: 13486 个 (61.9%)
```

### 精度（在唯一匹配子集上）
```
已知配对 358 对中：
  形状唯一且一致   = 30
  唯一但不一致     =  1
  不唯一/未覆盖    = 327
→ 精度 96.8% (30/31)
```

## 两个关键结论

### 1. 方法本身可靠
唯一匹配时精度 96.8%（31 次里错 1 次），足够用于"给函数贴名字"。

### 2. 但**改过的函数恰恰匹配不上**（358 对里 327 对未覆盖）
这符合预期：修补改变了函数体，形状自然不同。
**而这 358 个正是我们要找的修补点。**

## 因此正确的链条是

```
KDK（macOS 27.2，带 DWARF）
   │  形状匹配（同一份修补代码，形状一致）
   ▼
iOS 27.2 内核（已修版本）           ← 这一步能配上
   │  kfunc 已给出的 358 对配对
   ▼
iOS 27.0.1 内核（未修版本）         ← 名字随之带过来
   │
   ▼
读 27.0.1 的代码，找缺失的检查
```

**关键点：CVE 的修补同时存在于 macOS 27.2 和 iOS 27.2，
所以 KDK 里那个"已修好的函数"能和 iOS 27.2 的对应函数匹配上，
再借 kfunc 的配对把名字带到 27.0.1。**

## 预期产出（KDK 到手后）
- 13486 个函数（61.9%）可直接获得高置信名字
- 358 个改动函数通过"KDK → iOS 27.2 → 配对 → iOS 27.0.1" 链条获得名字
- 8 个候选可从"未知偏移"变成"有名有姓的子系统函数"
