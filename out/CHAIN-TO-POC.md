# 从"补丁差分"到"PoC"的完整链路

> 这条链每一步都有明确的输入、产物和判定门。当前进度：**S1 → S2 交界**。

## S0 补丁地图（已完成）
- 输入：27.0.1 (24A446) / 27.2 RC (24B115) 的 kernelcache
- 产物：117/301 kext 有改动；2,273/197,356 函数（1.2%）；每个改动函数的偏移对
- 判定：自比对必须为 0（已验证）；形状哈希下误报率 ~2%

## S1 候选分级（进行中）
- 输入：S0 的偏移对
- 三个维度打分：
  1. **可达面**：kext 是否面向用户态（IOUSBHostFamily / IOReportFamily / ANE / AGX / IOHID …）
  2. **检查类型**：新增边界检查（越界类）> 新增位域检查 > 新增判空（多为 DoS）
  3. **体积增长**：+100B 以上通常意味着新增了完整校验块，而非重排
- 产物：126 个候选（17 个面部 kext），头部是 ANE
- 判定：能在反汇编里肉眼指出"新增的那几条 cmp/b.xx"；指不出就丢

## S2 根因还原（下一步，当前卡点）
- 输入：单个候选函数在 27.0.1 侧的反汇编
- 要做的事：
  1. 找到被校验的字段（`ldr w?, [x?,#imm]` 里的 offset 就是结构体字段）
  2. 反推原版缺失的不变式（"这个字段应当 < 表长度，但没查"）
  3. 确定对象类型（哪个 IOKit 类 / 哪个内核结构）
  4. 写出一句话的 bug 陈述 + 触发条件
- 工具：Ghidra（交叉引用、结构体重建）、`funcdiff.py`、`strxref.py`
- 卡点：**符号表被 strip**，函数无名，需手工标注
- 判定：能写出"输入 → 缺检查 → 后果"三句话，否则丢弃

## S3 可达性证明
- 输入：S2 的函数
- 要做的事：
  1. 沿 `bl` 向上回溯到派发入口（`xref.py` 已可用）
  2. 判定入口类型：`IOExternalMethod` 选择子 / syscall / XPC 服务
  3. 若为 external method，还原 dispatch 表项：`{action, scalarIn, structIn, scalarOut, structOut}`（`dispatch.py`）
  4. 查该服务的 entitlement 与沙箱规则：普通 app 能否连
- 判定：能从"沙箱内 app"调用到该入口 → 可作链的第一环；否则只能做辅助

## S4 输入构造
- 输入：dispatch 表项 + 结构体布局
- 要做的事：构造违反不变式的输入（越界的 selector、长度字段大于实际缓冲、构造 size 与 scalar 数量不匹配）
- 产物：一个可重复的触发用例（app 侧代码）
- 判定：能稳定进入 S2 那个函数（靠日志/崩溃点确认）

## S5 触发与观测
- 输入：触发用例 + 真机（iPhone18,2 / 27.0.1）
- 要做的事：跑 → 拉 `panic-full-*.ips` → `panic_triage.py` 聚类 → 对照寄存器判断是"可控"还是"纯 panic"
- 判定：崩溃点落在目标函数、且寄存器/PC 受输入影响 → 继续；只有 DoS → 回 S1

## S6 原语构造
- 从 bug 形态决定原语：
  - 越界读 → 泄漏（KASLR slide、对象指针）
  - 越界写 → 破坏相邻对象字段
  - 类型混淆 → 伪造对象
- MIE 约束：只能玩同 `kalloc_type` 内的复用；UAF 基本绝迹
- 判定：能读到一个已知值（如自身 `proc->p_pid`），或能写一个无害字段并验证

## S7 稳定化
- 把"能触发"变成"每次都能触发"：堆布局（`kalloc_type` 分区、喷射对象选择）、时序、重试
- 用 `oracle_check.py` 的五项断言锁定偏移表
- 判定：连续 20 次成功 ≥ 18 次

## S8 提权
- 数据面：改 `ucred.cr_uid`、`p_csflags`、sandbox label
- 验证：`getuid()==0`、跑未签名 arm64e 二进制
- 判定：能起 dropbear 占 2222 端口、`dpkg -l` 有输出

## S9 打包（不完美越狱成品）
- bootstrap 放 `/var/jb`，`launchctl bootstrap` 起服务
- 重启后重跑 app 重放链（semi-tethered）
- untether 需引导链持久化，A19 上判死
