### 关键：旧检查没有消失，是被搬到了另一条路径

27.2 的 `+0x13c`（即 `tbz` 的落点）：

```asm
+0x13c  ldr  x8, [x19, #0xa8]      ; ★ 原来在入口的检查，搬到这里
+0x140  cbz  x8, +0x38             ; 极性反转：0 才回去继续
+0x144  bl   0xa95331c
```

### 语义变化

| | 27.0.1 | 27.2 |
|---|---|---|
| 进入主流程的条件 | `this->0xa8 == 0` | **`arg1->0xc` bit0 == 1**（新） |
| `this->0xa8 != 0` 时 | 直接走日志/退出 | 先看 `arg1->0xc`，再走日志/退出；若 `arg1->0xc` bit0 == 0 **且** `this->0xa8 == 0` 才回到主流程 |

⇒ **27.2 给这个入口加了一个「调用方传入对象的状态位」前置条件。**
`x1` 是调用方给的第一个参数，`+0xc` 的 bit0 是个状态位。
这不是错误码返回（`tbz` 落点不是错误返回），是**流程分支**，所以失败模式不是 `IOReturn`。

### 判断

- **和 `+0xf1` 同类**：都是「读某个对象的字节位 + 条件跳」，但**对象不同**（`+0xf1` 是 `this` 的 IOSurface 子对象，这里是**参数对象** `x1`）
- `com.apple.security.sandbox` 是 S4 沙箱本体的组件，但这个函数读的 `this+0x46` / `this+0x60` / `this+0xa8` 形态更像**通用容器/链表析构**（`ldrh count` + `ldr array` + 循环 `bl`），不一定是策略判定
- **要定性必须知道 `x1` 的对象类型**。这需要找这个函数的所有 `bl` 调用者，看 `x1` 从哪来。**我能做，但要另开一轮。**

## 4. 位域搬迁的两个样本（证明规则 6 不是空转，并留档）

```diff
# 0xa8ec158 -> 0xa93a4a4   2336 B -> 2336 B   +2/-2
- ldrb w8,[x20, #1]
- tbz  w8,#7,#5
+ ldrb w8,[x20, #2]
+ tbz  w8,#0,#5
```

```diff
# 0xa8eca78 -> 0xa93adc4   184 B -> 184 B   +2/-2
- ldrb w8,[x2, #1]
- tbnz w8,#7,#13
+ ldrb w8,[x2, #2]
+ tbnz w8,#0,#13
```

指令**一条没加**，字节偏移 `+1`→`+2`、位号 `7`→`0`。这是同一个标志位因为结构体布局变化搬了位置，
**不是新检查**。这类必须排除，否则每一批都会刷出假信号。
