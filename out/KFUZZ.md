# KFUZZ：契约精确 + 内容随机的内核 user client fuzzer

> 生成的 harness：`harness/kfuzz/main.m`（已交叉编译通过，50336 字节）
> 状态：**已就绪，等设备空闲后派发**

## 0. 为什么换方法

前 12 轮全部是静态分析 + 定点动态测试，结论全是负面。
根因分析：

```
Apple 把长度校验分散在多层：派发表 -> handler -> callee
任何单层静态扫描都会把「别处有校验」误判成「这里没校验」
```

本项目所有假阳性（S2、外方法越界读/写、GPU wildcard）**全部**源于这一条。
检测器只跟 `b` 不跟 `bl`，而校验恰恰在被调函数里。

**fuzzer 不受这个限制**：它不关心校验收在哪一层，只问「给这个输入，内核会不会出错」。

## 1. 设计

**契约精确**（上一轮实测得到的硬规则）：
```
scalarIn、structIn、scalarOut、structOut 必须 == 派发表声明值
放大任一个 -> 0xE00002C2，根本进不了 handler
```
所以长度固定，**只随机化内容** —— 这正好打「输入缓冲区内部字段被当下标/偏移」这一类，
而这一类是静态分析结构上看不见的。

两种内容模式交替：
```
mode 0   纯随机字节
mode 1   随机小整数 u32（0..0x1000）—— 更容易命中索引/偏移类
```

## 2. 目标（32 个，均有声明的输入结构）

| 服务 | type | 目标数 |
|---|---|---:|
| `IOSurfaceRoot` | 0 | 12 |
| `IOMobileFramebuffer` | 0 | 9 |
| `AGXAcceleratorG18P` | 1 | 8 |
| `AppleJPEGDriver` | 0 | 3 |

最大 `structIn` = **1760 字节**；8 个目标另有输出结构。
`IOSurface` 的 sel 27/87 输入 **160 字节**，是重点目标之一。

## 3. 崩溃可复现性

每轮调用前写：
```json
{"k":"@pre","it":<回合号>,"ti":<目标索引>,"svc":"...","sel":N,"m":<模式>}
```
`it` 同时是 **PRNG 的迭代序号**，配合 `seed` 可完整重放：
```
./kfuzz <seed> <rounds> <start=it>
```
panic 后从 `@pre` 的 `it` 重放即可定位。

## 4. 判据

- `kr` 变化的模式（同一 selector 从 BadArgument 变成别的码）= 越过校验
- **panic** = 最有价值，说明该输入触发了内存错误
- 挂起 = DoS 级，记录并跳过

## 5. 边界

- 不碰 `harness/israce/`
- 每次运行前记录 panic 计数（当前 **5**）
- 目标宿主是专用测试机，panic 属预期数据
