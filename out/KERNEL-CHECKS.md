# kernel 三条「新增错误返回」核查：问 1 + 问 2 + 分级

可达性（问 4）按父指示跳过：chained fixups 里 59% 是 BIND，静态搜不到，需要先解 imports 表。

**先给最重要的结论：这 3 条里 2 条是我自己分类器的误报，1 条是真的，且是真的那条落 S 级。**

---

## 0. 我的分类器错了，先说清楚错在哪

`kdiff_all.classify()` 判「新增错误返回」的条件是：add 里有 `movk #0xe000` + 有 `cmp`/条件跳。
**这个条件没有检查 27.0.1 侧是否本来就有同一个错误码构造。**

第 1、2 条正是这样：`mov w9,#0x2c2 ; movk w9,#0xe000`（`0xE00002C2` kIOReturnBadArgument，
`sub w0,w9,#3` → `0xE00002BF` kIOReturnBadMessageID）**两侧都有**。

已修：现在要求 `movk #0xe000` 不出现在 `old_tokens` 里。跑 IOSurface 复验仍是 2 条，没误杀。
顺带新增了「无条件读-改-写清位」判据（下面第 1 条就是要靠它抓）。

## 1. `0xb2c2ff8` → `0xb31911c` ｜分级 **B**（不是检查，是状态位清除）

### 问 1：两侧原文（±8 条）

**27.0.1**（388 B，函数体从 +0x18 起）：

```asm
+0x18  mov   x8, x0
+0x1c  mov   w9, #0x2c2
+0x20  movk  w9, #0xe000, lsl #16
+0x24  ldr   x10, [x0]
+0x28  ldr   w10, [x10, #0x20]

+0x38  ldr   x22, [x8, #0x18]

+0x40  cmp   x9, #3
+0x44  b.ne  +0x170

+0x5c  b.lo  +0x170
```

**27.2**（388 B）：

```asm
+0x18  mov   w10, #0x2c2
+0x1c  movk  w10, #0xe000, lsl #16
+0x20  ldp   x11, x21, [x0]        ; 融合：x11=[x0], x21=[x0+8]
+0x24  ldp   w9, w8, [x0, #0x10]   ; 融合：w9=[x0+0x10], w8=[x0+0x14]
+0x28  ldr   x22, [x0, #0x18]
+0x2c  ldr   x12, [x22, #8]        ; ★ 新增
+0x30  and   x12, x12, #0xfffffffffffffeff   ; ★ 清 bit 8 (0x100)
+0x34  str   x12, [x22, #8]        ; ★ 新增

```

**完整 diff 只有 1 处实质改动**（其余是 `ldp` 融合与分支目标重排）：
四条检查一条没少、一条没加，**没有任何新分支、也没有删除分支**。

### 问 2：被跳过的路径在 27.0.1 上做什么

**没有被跳过的路径。** 27.2 的操作是**入口无条件执行**的清位：`[(x0+0x18)+8] &= ~0x100`。

这个函数两侧共同做的大动作（27.0.1 走过、27.2 也走）：
1. 四次校验通过后，取 `[x22+0x28]`、`[x22+0x20]`，各做一次 **vtable 槽 0x38 + `superClass` 链遍历**（`ldr x8,[x16,#0x38]! ; blraa`）——
   典型的 **OSObject 类型受检转换**，比对常量 `0xb7b2000+0xd78` 与 `+0xe18`
2. `bl 0xab4a260` 把内容填进 `x22+0x40` 的 **0x80 字节缓冲**，要求返回值 `<= 0x7f`
3. **经调用方传入的 `x2` 做 vtable 槽 0xac0 的间接调用**
4. 把 **60 字节结果**写进 `[x0+8]`：`+4 := 0x3c`、`+0x1c`（8 字节常量）、`+0x24`（16 字节常量）、`+0x34 := 0`

### 分级：**B**，但按新判据它属于「新增字段写」

- 不是「新增检查」→ 不是 S/A
- 也没找到 27.0.1 的等价清位（27.0.1 侧完全没有任何 `and ...#0xffffffff...`）→ 不是搬家
- **它是一处新增的无条件状态位清除**，方向是「进函数先把 bit8 抹掉」

`bit 8` 在 `[(x0+0x18)+8]` 这个 64 位字里。这个对象带 OSObject 风格的受检转换，
字形上是一个 **IOKit 基类对象**。清 bit8 的语义（哪一位、谁置的）**未定** —— 没追到置位点。

## 2. `0xb2d0348` → `0xb32665c` ｜分级 **B**（与第 1 条同构）

27.2 入口：

```asm
+0x18  mov   w10, #0x2c2
+0x1c  movk  w10, #0xe000, lsl #16
+0x20  ldp   x11, x22, [x0]
+0x24  ldp   w9, w8, [x0, #0x10]
+0x28  ldr   x23, [x0, #0x18]
+0x2c  ldr   x12, [x23, #8]        ; ★
+0x30  and   x12, x12, #0xfffffffffffffeff   ; ★ 同样清 bit 8
+0x34  str   x12, [x23, #8]        ; ★
+0x38  ldr   w11, [x11, #0x20]
+0x3c  sub   w0, w10, #3
+0x40  cmp   w11, #4                ; 注意：这条比的是 4，第 1 条比 3
```

**与第 1 条同一处修复，对象类型判据从 `==3` 换成 `==4`** ⇒ 同一函数族的两个变体。
问 2 同上：**没有被跳过的路径**，是无条件清 bit8。

⇒ **这两条合起来是一个系统性修复：一族函数，入口统一清 `[(x0+0x18)+8]` 的 bit8。**
这比单条更有价值 —— 它说明 27.0.1 存在一个「bit8 残留」的状态问题，影响至少 2 个变体。

## 3. `0xb348450` → `0xb39e868` ｜分级 **S（强候选）** ← 唯一真货

### 问 1：两侧原文

**27.2 在函数体前面加了整整一个校验前导块**：

```asm
+0x00  bti   c
+0x04  mov   w8, #0x2d8
+0x08  movk  w8, #0xe000, lsl #16        ; 0xE00002D8
+0x0c  mov   w9, #0xc0
+0x10  bic   w9, w9, w1                  ; ★ w9 = 0xC0 & ~w1
+0x14  cbnz  w9, +0x20                   ; ★ 越界位非零 → 进函数体
+0x18  sub   w0, w8, #0x16               ; ★ 否则 w0 = 0xE00002C2
+0x1c  ret                               ; ★ 直接返回
+0x20  pacibsp                           ; 原函数体从这里开始
```

即 **`if (w1 & ~0xC0) != 0 → return kIOReturnBadArgument`**，只允许 `w1` 取 `0xC0` 的子集（bit6/bit7）。

**27.0.1 的入口完全没有这一块**，直接 `pacibsp; sub sp,sp,#0x40; stp ...`。
我在 27.0.1 整个函数（596 B）里搜 `bic` 和 `#0xc0` ⇒ **`[]`，零命中**。
**⇒ 确认不是搬家，是新增。**

### 问 2：被跳过的路径在 27.0.1 上做什么（核心）

27.0.1 在 `w1` **不受任何约束**的情况下会走进去，并对 `w1` 做这三件事：

```asm
+0x38  tbnz  w20, #0x12, +0x80      ; 先看 [x0+0x20] 的 bit18
+0x4c  ldr   w12, [x9, #0x4f8]
+0x50  add   x13, x8, #8
+0x54  casa  x11, x12, [x13]        ; ★ 原子 CAS 改内核对象字段
+0x58  cmp   x11, #0
+0x60  ands  w8, w1, #0x600         ; ★ 从 w1 抽 bit9/bit10
+0x68  orr   w1, w8, #1             ; ★ 重写 w1 = (w1 & 0x600) | 1
+0x78  mov   x0, x19
+0x94  mov   x1, x9
+0xa0  mov   x1, x21                 ; ★ 改写后的 w1 作为参数传给下游调用
+0xa8  ands  w8, w1, #0x600
+0xb8  cmp   w8, #0x10               ; ★ 再参与分支判定
```

**三项具体动作**（不是「跳过了」）：

1. **`w1` 被重写成 `(w1 & 0x600) | 1`**
2. **改写后的 `w1` 作为 `x1` 传进下游调用**（`mov x1, x21` 之后紧接着的 `bl/braa`）
3. **参与 `cmp w8, #0x10` 的分支决策**，同一函数内还有一次 `casa`（原子交换 `[[x0+0xa8]+8]`）

⇒ 按父的判据：**改标志位 + 传入下游** ⇒ **S 级**。

### 一个更强的推论（值得注意）

新检查只允许 `w1 ∈ {0, 0x40, 0x80, 0xC0}`，而这几个值 **`w1 & 0x600` 恒为 0**。
也就是说：**27.2 加上这道校验后，`+0x60` 处那段「抽 bit9/bit10」的代码变成了死代码**。

⇒ 这不是「补一个边界检查」，而是**把 `w1` 的合法取值从「任意 32 位」收紧到「两位」**，
连带让旧的分支逻辑失效。这种改法的动机通常是：**旧调用方传了不该传的位，而
`(w1 & 0x600) | 1` 会把越权位带进下游**。

### 分级：**S**

- 被拦路径的效果 = **改权限/模式位 + 传入下游调用 + 原子改内核对象字段**
- 27.0.1 **无等价判断**（全函数 0 命中 `bic`/`#0xc0`）
- 可达性未定（按父指示跳过）

**⇒ 这是三条里唯一值得单开一轮、去解 chained fixups imports 表换可达性的一条。**
