# 方法缺陷：BTI 单一边界检测会合并无 BTI 的函数

**日期**：2026-11-01 02:45
**影响范围**：本工程全部 dChk / 函数级差分结果

## 一、缺陷

此前用「`BTI c`（`5f 24 03 d5`）出现位置」作为函数起点。
但 ARM64e 内核里**有一部分函数不发 BTI**：它们只被直接调用（`bl`），
不走函数指针/间接跳转，因此链接器可以省略 BTI 指令。

这类函数的典型开头是**直接 `pacibsp`**：
```asm
0xfffffe000ad4cce0  pacibsp          ← 没有前置 bti c，这是一个函数起点
0xfffffe000ad4cce4  sub sp, sp, #0xb0
```

## 二、后果

合并后的「函数」会包含多个真实函数，导致：
- 指令数虚高
- **dChk 虚高**（把相邻函数的条件分支算进同一个函数）

实例：27.2 `com.apple.kernel` 的 `0xad4cc38` 被报成
「1228 条指令 / 41→492 个检查 / dChk=+451」，
实质是 **若干相邻函数被合并**，该数字无意义。

## 三、修正规则

函数起点判定改为：
```
word ∈ { BTI c, PACIBSP }
AND ( offset == 0
      OR 前一条 4 字节 ∈ { ret, retab, nop, 0x00000000 }
      OR 前一条指令的 mnemonic ∈ { ret, retab, b, br } )
```

## 四、修正后的复核结果

| 目标 | 原报 | 修正后 | 结论是否变化 |
|---|---|---|---|
| IOSkywalkFamily | dChk>0 = 0 | **dChk>0 = 0** | 不变（仍出局） |
| **AppleAVD** | 6 对，1 个 dChk=+5 | **5 对，1 个 dChk=+3** | **结论不变，仍成立** |
| AppleH16ANE | 155 对，42 个 dChk>0 | 158 对，**43** 个 dChk>0 | 不变（出局依据是可达性） |
| com.apple.kernel | 235 对，99 个 dChk>0 | 见 `/tmp/kchk2.txt` | 需重看 |

### AVD 的关键复核
修正后函数实际起点是 `0x8707c34`（不是我原先认的 `0x8707cf0`），
`0x1000` 字节内**无独立 pacibsp 起点**，说明原边界虽偏后但未跨越函数。
27.2 新增的检查块经重新提取，内容一致：

```asm
cbnz w10, ...        ; 状态
cbnz w10, ...
cbz  x9, ...         ; 空指针
b.hs  fail           ; ★ 溢出检测
b.hi  fail           ; ★ 容量检查
csel  w1, w24, w10, lo   ; ★ 截断到 min
csel  w1, w3,  w8,  lo   ; ★ 另一处截断
```

**→ AppleAVD 的「27.0.1 拷贝路径缺容量校验」结论在修正方法下依然成立。**

## 六、第二个缺陷：按位置配对会产生假配对（03:00）

### 表现
修正边界后，`com.apple.kernel` 出现两个「0 个检查 → 50 个检查」的诱人结果：

```
0 → 50   0xfffffe000acfaf88 → 0xfffffe000ad4cce0   +470 指令
0 → 29   0xfffffe000ae8a4b8 → 0xfffffe000aedd7c0   +140 指令
```

### 实测：这是假配对

27.0.1 `0xacfaf88`（9 条指令，零校验的地址计算器）：
```asm
bti   c
ldr   x8, [x0, #0x38]
str   x8, [x2]          ; *out1 = obj->field38
ldr   x8, [x0, #0x40]
add   x8, x8, x1        ; obj->field40 + 参数1
str   x8, [x3]
mov   w0, #1
ret
```

27.2 `0xad4cce0`（前 40 条）：
```asm
pacibsp
...
pacda x16, x17
str   x16, [sp, #0x20]      ; 构造 PAC 签名的回调结构
ldr   d0, [x9, #0x9f0]
str   d0, [sp, #0x28]
pacia x16, x9
str   x16, [sp, #0x30]
stp   x16, x0, [sp, #0x38]
```

**两者语义完全不同**：一个是取地址，一个是注册回调。
`SequenceMatcher` 在 `replace` 块内按**位置**一对一配对，
当一侧有函数插入/删除时必然错配。

### 结论
- 「0→50」「0→29」是假象，**不是真发现**
- 全部「按位置配对」得出的 dChk 排名，在功能增删密集的区域**都不可信**
- 只有**人工反汇编确认过语义对应**的配对才可用

## 七、修正后的可信度分级

| 级别 | 含义 | 本工程实例 |
|---|---|---|
| **A 级** | 人工反汇编逐条确认两侧语义对应 | **AppleAVD `0x8707c34` ↔ `0x873e224`** |
| B 级 | 配对可靠（函数数一致、无插入），dChk 可用 | skywalk（1909 = 1909） |
| C 级 | 有插入/删除，配对可能错位 | kernel（14961 → 14993） |
| **D 级** | 已证伪 | kernel 的 0→50 / 0→29 |

## 八、当前唯一 A 级结论

**AppleAVD 27.0.1 的拷贝路径缺少「偏移+长度 ≤ 容量」校验与溢出检测。**

证据（人工逐条比对，边界已验证未跨函数）：
```asm
27.2 新增： cbnz w10 / cbnz w10 / cbz x9
             b.hs  fail          ← 溢出检测
             b.hi  fail          ← 容量检查
             csel  w1, w24, w10, lo   ← 截断到 min
             csel  w1, w3,  w8,  lo   ← 另一处截断
27.0.1 同位置： mov x0, x20 / mov x2, w24 / mov x3, x21 / bl
```

未决：该长度字段的数据来源（是否用户可控）。

## 九、缺陷三：`dchk2.py` 的边界规则**少切约 6800 个函数**（A 方向实证，2026-11-01）

### 实测
27.2 内核里 `pacibsp` 共 **16498** 个，我的规则只认 **9691** 个，
残留 **6807** 个无一例外都后接栈帧建立指令：

| 后接指令 | 数量 |
|---|---|
| `sub`/`add sp` | 3974 |
| `stp`/`str [sp]` | 2829 |
| `mov` | 4 |

**原因**：`pacibsp` 前一条若是 `bl`（调用 noreturn）或 `brk`，不在我的允许集里。

### 修正规则（已验证）
```
起点 = 任一 PACIBSP  ∪  (BTI c 且下一条 ≠ PACIBSP)
```
修正后函数数从 14961/14993 变成 **23277/23332**。

### 后果
旧口径排名第一的 `0xabc6850`(+45) 系列，实际是 **2 个函数被并成 1 个**。
所有基于旧边界（含 dchk2.py）的数值都要重算。

## 十、缺陷四：**dChk 会把搬走的分支算成新增**

### 实证
`0xaef4690 → 0xaf48310`：27.2「新增」侧的 `cmp x8,#0xc; b.hi` ×2
与 27.0.1「删除」侧的指令**完全相同**，纯基本块重排，dChk 却报 **+5**。

### 修正
必须配「**校验签名多重集差分**」：只重排不增语义时 dChk>0 而净签名 = 0。
159 个候选里有 **15 个**属此类。

判据工具：`/tmp/ksig.py all`

## 十一、同类误判第六次（A 方向踩的，记录备查）

`0xacc5164 → 0xad16ae4`（dChk=+6）签名级像双向边界检查
（`CMP lo x,x` / `CMP hs x,x`），逐条读完是**乘异或哈希表查找**：

```
eor / mul 常数 0x7fb5… / eor lsr#27 / mul / and 表容量-1 / ubfiz #5
cmp x10, w10, sxtw      ← 只是符号扩展比较
```

而且 27.0.1 版本只有 44 条 `str xzr,[x19]` —— **空桩**，27.2 才实现。

**判据**：出现「乘法常数 + 移位异或 + 与表容量掩码」三者同时出现，
就不要当边界检查。

## 十二、最终边界规则（替代全部旧版本）

```
def func_starts(body):
    S = set()
    for i in range(0, len(body)-3, 4):
        w = body[i:i+4]
        if w == PACIBSP:                       # 任一 PACIBSP 即起点
            S.add(i)
        elif w == BTI and body[i+4:i+8] != PACIBSP:
            S.add(i)                           # BTI 且下一条不是 PACIBSP
    return sorted(S)
```

**这条规则同时修掉了缺陷一和缺陷三。**
旧版 `dchk2.py` 只有缺陷一的半修，需按上式更新。
