# 新方向：公开漏洞根因驱动（Public Ground Truth）

## 否定旧方向
- 不做“27.0.1 vs 27.2 差分后猜修补点”：改动可能是功能、缓存、重构、寄存器/地址重排。
- 不做“26 有而 27 没有”回归检测：26 的洞大概率早已在 27 修复，无法据此推导漏洞。
- 不做无覆盖率反馈的盲 fuzz。

## 唯一证据入口
按优先级：
1. **现成公开 PoC / reproducer**（最高）
2. **公开修复提交 + 明确根因**（WebKit Bugzilla、dav1d、FreeType、libpng 等）
3. **上游 issue 的崩溃样本或精确输入约束**
4. Apple 安全公告仅用来列 CVE 清单与影响面，**不能作为代码级根因证据**

没有以上任一证据，就不把它列为漏洞候选。

## 工作流
Apple 27.2 公告中的 CVE → 搜索公开根因/PoC/修复提交 → 提炼触发条件 →
在 app 沙盒内实现最小触发路径 → iPhone18,2 / 27.0.1 真机验证 →
保存输入、日志、崩溃报告。

优先：WebKit/JSC（公开源码与 Bugzilla）、dav1d/媒体解析、公开 PoC 可得的字体/图片/3D 模型问题。

## 验收标准
每条候选必须写明：
- CVE / 上游 issue / commit URL
- 公开根因（不是“函数变了”）
- 触发输入与 app 可达调用链
- 真机结果（崩溃/无异常/未验证）

没有公开根因或实测证据的条目不得写成漏洞结论。
