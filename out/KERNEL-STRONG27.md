> 起因：`KERNEL-137-TRIAGE.md` 的 159 个候选是按 **dChk（分支数）** 筛的。
> `out/patches/com_apple_kernel.md` 用的是**指令形态**，两者不是同一个集合。
> 本文件检查后者，结论与 `KERNEL-UAF-SIG.md` 冲突。

## 3. ★ 与 `KERNEL-UAF-SIG.md` 的冲突（已核实）

那份文件写：「新增 retain/release 的函数 **0 个**」。

**实测：6 个「新增原子/CAS」里，只有 2 个是真的新增内联原子指令：**

| 函数（27.0.1） | 大小变化 | 真新增原子 | 判定 |
|---|---|---|---|
| `0xac248cc` | 492→492 B | 无 | **假信号**（只有分支位移 `b.ne #37→#31` 变了） |
| `0xad04d3c` | 128→152 B | 无 | 标签错，非 CAS |
| `0xad04dbc` | 136→152 B | 无 | 标签错，非 CAS |
| **`0xad278ec`** | 196→**252 B** | **`casl w2,wzr,[x20]`** | 真 |
| **`0xb0a29fc`** | 404→**496 B** | **`casa x8,x9,[x21]` + `casl w2,wzr,[x21]`** | 真（retain+release 成对） |
| `0xb1530b0` | 488→516 B | 无 | 标签错 |
| `0xb0ebd14` | 2648→2680 B | 无 | 标签错 |

**根因**：`KERNEL-UAF-SIG.md` 数的是**对 retain/release 辅助函数的 `bl` 调用次数**；
这两个修补用的是**内联 `casa`/`casl`，没有任何 `bl`** ⇒ 该类检测器完全看不见。

**⇒ 「0 个」这个结论是检测器盲区，不是事实。**

## 4. `0xb0a29fc` 的修补形态（最完整的一个）

```asm
; 新增
mov  x8, #0
mrs  x20, tpidr_el1        ; 当前 thread
ldr  w9, [x20, #0x4f8]     ; thread 上的 32 位字段
add  x21, x0, #0x58        ; 对象 +0x58
casa x8, x9, [x21]         ; 若 [x21]==0 则写入 w9（原子获取）
cmp  x8, #0
b.ne skip
ldr  w8, [x20, #0x4f8]
mov  x2, x8
casl w2, wzr, [x21]        ; 若 [x21]==w2 则清零（原子释放，带所有权比对）
cmp  w2, w8
b.ne skip
cbz  x19, skip
mov  x19, x0
add  x0, x0, #0x50
mov  x1, x20
mov  w2, #0
bl   <X>                   ; 以 (对象+0x50, thread, 0) 调用
mov  x0, x19
```

**语义**：把 thread 上的一个 32 位值原子地写进对象 +0x58 槽（仅当槽为空），
再带**所有权比对**地清回 0，然后执行动作。
**这是「对象 +0x58 的所有者槽」的无锁交接，典型竞态窗口修补。**

涉及字段：`+0x4f8`（thread 侧）、`+0x50` / `+0x58`（对象侧）。

## 5. 可达性：静态未能定性

```
0xb0f80f0（27.2）的直接 bl 调用点: 2 个
   -> 函数体 0xb13b778  -> 调用者 0xac74f38 -> 函数 0xac74b48 -> 调用者 0 个
   -> 函数体 0xb1de3e0  -> 调用者 0xb12d3a0 / 0xb1e0ff0
      -> 函数 0xb12cdec / 0xb1e0a8c -> 再上一层 0xb1de3e0 / 0xb1f42fc -> 0 个
0xad7a788（27.2）的直接 bl 调用点: 0 个
```

**5 个相关函数（0xac74b48 / 0xb12cdec / 0xb1e0a8c / 0xb1de3e0 / 0xb1f42fc）
全部：无字符串引用、无直接调用者 ⇒ 只能经间接分派到达。**

⇒ **无法用静态方法定性属于哪个子系统。** 需要动态手段（断点/内核日志），本工程没有。

## 7. 纪律

- 本轮静态分析基于 `out/kc.27.0.1.full` / `out/kc.27.2.ga.full`，未用设备
- `0xac248cc` 这个「假信号」案例值得记住：**分支位移变化会让 diff 窗口里出现未变的指令，
  被形态检测器误判成「新增」**。凡报「新增 X 指令」，必须核对**两侧函数体大小**和**该指令是否只在 `+` 侧**
